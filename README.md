# Karan Sapalia — Portfolio v10 (MERN)

A portfolio built as a stylish JRPG-style game menu: red/black/white, angled cuts, torn paper, halftone accents and snappy menu motion. All art is original SVG; game names and short signature phrases appear only as plain text in the site's own lettering.

> **Status:** v10 is feature complete: the intro ("The Heist"), Persona-style menu, HUD, cursor, scroll rail, all six screens (Missions with filters, About, Hideout, Status, Journey, Contact on the calling card), the 404 page, the SOUND button, the icon set and the motion catalogue. Open items are the files you need to add (photo, résumé, screenshots, music) and the `TODO`s in `shared/seedData.js`. The old vanilla site is in `legacy/`.

## Stack

- **client/**: React + Vite, GSAP + ScrollTrigger, Lenis, Framer Motion (UI states only), plain CSS
- **server/**: Node + Express, Mongoose (MongoDB Atlas), helmet, cors, compression, express-rate-limit, JWT, optional Nodemailer
- **shared/seedData.js**: the single source of content. The server seeds MongoDB from it, and the client bundles it as a fallback so the site is never empty if the API is down.

## Run locally

```bash
npm install          # installs both workspaces
npm run dev          # API on :5000, site on :5173
```

No database needed to start: without `MONGODB_URI` the API runs in **demo mode** (in-memory seed data; admin edits and messages last until restart).

### With MongoDB + admin

1. Copy `server/.env.example` → `server/.env`; set `MONGODB_URI`, `ADMIN_PASSWORD`, `JWT_SECRET` (and SMTP vars if you want contact emails).
2. `npm run seed` loads projects, clips, journey and skills.
3. `npm run dev`.

## API

| Method | Route | Notes |
| --- | --- | --- |
| GET | `/api/health` | `{ ok, db }` |
| GET | `/api/projects` · `/api/clips` · `/api/journey` | sorted by `order` |
| GET | `/api/skills` | `{ stats, items }` |
| POST | `/api/contact` | `{ name, email, message }` — validated, tag-stripped, 5 per 15 min per IP, stored; emails you if SMTP is set |
| POST | `/api/admin/login` | `{ password }` → `{ token }` (8h JWT), 10 attempts per 15 min |
| GET | `/api/admin/messages` | Bearer token |
| POST / PUT / DELETE | `/api/admin/:kind[/:id]` | `kind` = `projects` · `clips` · `journey`; unknown fields are dropped |

## Where things live

- Tokens (colours, spacing, type scale, easing, `--photo-mode`, `--rail-w`): `client/src/styles/tokens.css`
- Shared components: `client/src/components/` — `ui.jsx` (SlantButton, RansomTitle, TornEdge), `CallingCard`, `MaskEmblem`, `ScreenFrame`, `DialogueBox`, `StickerArt`, `Wipe`, `Portrait`, `ScrollRail`, `Hud`, `MainMenu` (pause menu), `Cursor`, `Loader`
- Menu character and transitions: `client/src/components/menu/PhantomCharacter.jsx` (original SVG figure wearing the site's mask; `pose` prop, `ref.confirm()`, `ref.cardRect()`, so the art can be swapped for Lottie/Rive/sprites without touching menu logic) and `client/src/components/menu/TransitionLayer.jsx` (six scenes: SHATTER, CURTAIN + INK, SLASH, BARS, PAPER RIP, SHOCKWAVE CARD; Esc finishes one instantly, reduced motion uses a 150ms fade). Dev only: set `window.__trSlow = 0.15` in the console to watch a transition in slow motion.
- Motion catalogue (magnetic buttons, scroll-velocity skew, counters, bar fills, heading reveals, sticker pops): `client/src/lib/motion.js`, started from `Home.jsx` once every screen has mounted
- 404: `client/src/NotFound.jsx`; icons and share image: `scripts/icons.mjs`
- Intro: `client/src/sections/Heist.jsx` + `styles/heist.css` (one 100-unit pinned timeline; beats are documented at the top of the file)

## Scripts

`npm run dev` · `npm run build` · `npm run seed` · `npm run lint` · `npm run format` · `npm run photo` · `npm run photo:cutout` · `npm run icons`

**Icons:** `npm run icons` (sharp + png-to-ico) rebuilds everything in `client/public/` from `scripts/icons.mjs`: `favicon.svg`, `favicon-away.svg` (shown while the tab is hidden, alongside the "COME BACK, THIEF." title), `favicon.ico` (16/32/48 from a simplified small mask), `favicon-32.png`, `apple-touch-icon.png`, `icon-192/512.png`, `icon-maskable-512.png`, `og-image.png` (1200x630, rendered in your installed Chrome so it uses the site fonts) and `site.webmanifest`.

**Visual QA (dev only):** with the dev server running, `node scripts/qa.mjs name:1280x720:p0.52 menu:360x740:menu about:1280x720:about` drives your installed Chrome and saves screenshots to `docs/qa/`. The `?qa=` URL hook (dev builds only) jumps to an intro progress (`p0.52`), a section id, or opens the menu.

## Deploy

The site is static (Vercel), the API is a small Node service (Render), the data lives in MongoDB Atlas. The site still works if the API is down: every read has a bundled fallback and only the contact form needs the API.

1. **MongoDB Atlas**: create a free cluster → Database Access: add a user → Network Access: allow Render (0.0.0.0/0 is the easy option on the free tier) → Connect → copy the `mongodb+srv://…` string. Put the database name in it (`…mongodb.net/portfolio`).
2. **API on Render**: New → Blueprint → pick this repo (it reads `render.yaml`), or create a Web Service from the repo root with build `npm install` and start `npm start -w server`. Set `MONGODB_URI`, `ADMIN_PASSWORD`, `CORS_ORIGIN` (your site URL, no trailing slash; comma-separate several), and the SMTP variables if you want contact emails. `JWT_SECRET` is generated for you. Then run `npm run seed` once with `MONGODB_URI` set (locally is fine) to load the content. Check `https://YOUR-API.onrender.com/api/health`. Free instances sleep, so the first contact-form send after a quiet spell can take ~30 s.
3. **Site on Vercel**: import the repo, leave the root directory as the repo root (`vercel.json` sets the build and the single-page rewrite, which is what makes the 404 page work on deep links). Add the environment variable `VITE_API_URL=https://YOUR-API.onrender.com` and deploy.
4. **Before you share it**: set `og:url` and the absolute `og:image` in `client/index.html` to your domain and redeploy; add your photo, résumé and (optionally) `bgm.mp3` (see "Files you need to add"); fill the `TODO`s in `shared/seedData.js`.

Unknown URLs return the app's own "NO TREASURE HERE." page with HTTP 200 (single-page-app routing); the page carries `noindex` so search engines skip it.

## Performance and accessibility (measured)

Lighthouse 12 against the production build (`npm run build`, then `npx vite preview` in `client/`), headless Chrome, default throttling:

| | Performance | Accessibility | Best practices | SEO |
| --- | --- | --- | --- | --- |
| Desktop | 93 | 100 | 100 | 100 |
| Mobile (4x CPU slowdown) | ~60 | 100 | 100 | 100 |

Mobile performance is below the 85 target: the scroll-driven intro and the stacked mission panels are script and layout heavy, and Lighthouse's mobile profile slows the CPU 4x. What is already done: non-blocking font loading, an instant static first frame, screens after the intro mount in three steps after it is on screen, and scroll-skew is scoped to the few elements that use it. Next levers if you want more: code-split the mission mocks and the Hideout, trim framer-motion (used only by the HUD tag and the menu), or serve a lighter intro on small screens.

Reduced motion: with `prefers-reduced-motion` on, the intro, scroll effects, reveals, counters, magnetic buttons and marquees are off and every screen shows its final state (`QA_REDUCED=1 node scripts/qa.mjs …` captures it).
